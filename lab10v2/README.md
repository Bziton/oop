### 5. Реалізував запит 1: фільтрація та join

Студенти до 20 років на курсі «Programming Basics».

```csharp
var q1Query =
    (from s in students
     join c in courses on s.CourseId equals c.Id
     where c.Title == "Programming Basics" && s.Age < 20
     select s).ToList();

var q1Method = students
    .Join(courses.Where(c => c.Title == "Programming Basics"),
          s => s.CourseId,
          c => c.Id,
          (s, c) => s)
    .Where(s => s.Age < 20)
    .ToList();
```

### 6. Реалізував запит 2: об'єднання колекцій

Ім'я студента та назва його курсу.

```csharp
var q2Query =
    (from s in students
     join c in courses on s.CourseId equals c.Id
     select new { StudentName = s.Name, CourseTitle = c.Title }).ToList();

var q2Method = students
    .Join(courses,
          s => s.CourseId,
          c => c.Id,
          (s, c) => new { StudentName = s.Name, CourseTitle = c.Title })
    .ToList();
```

### 7. Реалізував запит 3: агрегація

Кількість студентів на кожному курсі. Використав `GroupJoin`, щоб курс без студентів не зникав із результату.

```csharp
var q3Query =
    (from c in courses
     join s in students on c.Id equals s.CourseId into enrolled
     select new { c.Title, Count = enrolled.Count() }).ToList();

var q3Method = courses
    .GroupJoin(students,
               c => c.Id,
               s => s.CourseId,
               (c, enrolled) => new { c.Title, Count = enrolled.Count() })
    .ToList();
```

### 8. Реалізував запит 4: наймолодший студент

```csharp
var q4Query =
    (from s in students
     orderby s.Age
     select s).First();

var q4Method = students.MinBy(s => s.Age)!;
```

### 9. Виміряв продуктивність

Запити LINQ виконуються відкладено, тому в кожному запиті стоїть негайне виконання (`ToList()`, `First()`, `MinBy()`). Без цього `Stopwatch` заміряв би лише створення запиту, а не його виконання.

Допоміжний метод `Measure` повертає результат, час першого запуску та середній час із 1000 повторів:

```csharp
static (T Result, double FirstMs, double AvgMs) Measure<T>(Func<T> query, int repeats = 1000)
{
    var sw = Stopwatch.StartNew();
    T result = query();
    sw.Stop();
    double firstMs = sw.Elapsed.TotalMilliseconds;

    sw.Restart();
    for (int i = 0; i < repeats; i++)
    {
        query();
    }
    sw.Stop();
    double avgMs = sw.Elapsed.TotalMilliseconds / repeats;

    return (result, firstMs, avgMs);
}
```

| Запит | Синтаксис | Перший запуск, мс | Середній, мс |
|-------|-----------|-------------------|--------------|
| 1. Фільтрація + join | запитів | … | … |
| 1. Фільтрація + join | методів | … | … |
| 2. Join | запитів | … | … |
| 2. Join | методів | … | … |
| 3. GroupJoin + Count | запитів | … | … |
| 3. GroupJoin + Count | методів | … | … |
| 4. Наймолодший (`OrderBy` + `First`) | запитів | … | … |
| 4. Наймолодший (`MinBy`) | методів | … | … |

Час залежить від комп'ютера, але співвідношення між запитами зберігається.

### 10. Висновки про продуктивність

- Обидва синтаксиси дають однаковий результат і майже однаковий час, бо компілятор перетворює синтаксис запитів на виклики методів.
- Перший запуск кожного запиту повільніший за середній час через JIT-компіляцію, тому однократні виміри на малих даних ненадійні.
- Найдорожчими зазвичай є запити з `Join` та `GroupJoin`: для них будується хеш-таблиця за ключем і створюються нові об'єкти (анонімні типи).
- `MinBy` проходить колекцію один раз за O(n), а `OrderBy` + `First` сортує її всю за O(n log n). На 15 елементах різниця непомітна, на великих колекціях `MinBy` швидший.

## Контрольні запитання

| № | Питання | Відповідь |
|---|---------|-----------|
| 1 | У чому різниця між відкладеним та негайним виконанням у LINQ? | При відкладеному виконанні запит не виконується в момент створення, а лише під час ітерації по його результатах (наприклад, у `foreach`). Негайне виконання відбувається одразу під час виклику методів на кшталт `ToList()`, `ToArray()`, `Count()`, `First()`. Тому якщо змінити джерело даних між створенням запиту й ітерацією, результат буде за новими даними. |
| 2 | Чим `Join` відрізняється від `GroupJoin`? | `Join` повертає плоский список пар елементів з однаковим ключем, а елементи без пари в результат не потрапляють. `GroupJoin` для кожного елемента першої колекції повертає групу відповідних елементів другої, тому елемент без пари теж лишається (з порожньою групою). У запиті 3 саме тому курс без студентів отримав би кількість 0. |
| 3 | Чому при вимірюванні часу запиту потрібен `ToList()` або подібний метод? | Через відкладене виконання: без нього `Stopwatch` заміряє лише створення запиту, який ще нічого не обчислив. `ToList()`, `First()` чи `MinBy()` змушують запит виконатися всередині виміру. |
| 4 | Чим `MinBy` відрізняється від `OrderBy().First()`? | `MinBy` проходить колекцію один раз і запам'ятовує мінімум, складність O(n). `OrderBy().First()` спочатку сортує всю колекцію, складність O(n log n), хоча потрібен лише один елемент. Результат однаковий, а на великих даних `MinBy` швидший. |
| 5 | Чи відрізняється продуктивність синтаксису запитів і синтаксису методів? | Практично ні: компілятор перетворює синтаксис запитів на виклики методів розширення (`Where`, `Select`, `Join` тощо). Вибір між ними залежить від читабельності: `join` та `let` зручніші в синтаксисі запитів, а `MinBy`, `Take`, `Skip` доступні лише як методи. |
